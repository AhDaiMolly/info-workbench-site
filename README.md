# 信息汇总工作台

一个放在 GitHub Pages 上的**个人资料记录管理工具**：你在网页里浏览、筛选、搜索、增删改自己的资料，数据存在你自己的 GitHub 私有仓库里，网页本身不保存任何数据。

- 应用全称：**信息汇总工作台**（所有界面、文档、导出文件名统一使用这个名称）
- 形态：纯静态网页（不需要服务器、不需要数据库）
- 初始数据：798 条记录 × 19 个字段，已全部迁移进数据仓，**一条不少**
- 适用对象：不需要懂技术的使用者；下面的每一步都按"照着点"写好了

## 一、整体结构：两个仓库各管什么

整套东西拆成**两个 GitHub 仓库**，这是整个方案的安全基础：

| 仓库 | 名称建议 | 可见性 | 装什么 | 不装什么 |
| --- | --- | --- | --- | --- |
| **站点仓** | `info-workbench-site` | **Public（公开）** | 网页代码（HTML/JS/CSS） | **一条真实数据都不装** |
| **数据仓** | `info-workbench-data` | **Private（私有）** | `data/records.json`（798 条记录）、字段定义、备份快照 | 不装网页代码 |

为什么要分两个：

- 站点仓是公开的，任何人都能打开。如果数据也放在这里，你的资料就等于公开了。
- 数据仓设成私有，并且令牌只授权这一个仓库 —— 即使令牌意外泄露，攻击者也碰不到你的其他仓库。
- 网页在运行时用令牌**临时**去私有数据仓取数据，取到的数据只存在你自己的浏览器内存/本地缓存里，不经过任何第三方服务器。

## 二、五分钟看懂：数据从哪来、到哪去

```
原始 Excel (798 条)
        │  一次性迁移脚本（tools/migrate.mjs）
        ▼
数据仓 data/records.json  ◄──┐
        │                    │ ① 网页用令牌读取（只读或写回）
        │ ② 网页写回（带 sha 乐观锁）│
        ▼                    │
   你的浏览器 <───────────────┘
   ├─ 筛选 / 搜索 / 看板 / 增删改
   ├─ 导出 JSON / Excel
   └─ 令牌与缓存只存在本机浏览器里（可随时清除）
```

- **令牌永远不会进入代码仓库**：闸门脚本 `scripts/check-no-data.mjs` 会在每次发布前扫描源码和构建产物，一旦发现令牌字面量就**直接阻断发布**。
- **令牌也不会写进网址**：不会出现在地址栏、不会出现在 GitHub 提交信息里。
- **断网也能用**：浏览器本地缓存着最近一次拉取的数据；离线时照常浏览、编辑，联网后再点"同步"写回。

## 三、部署步骤（第一次上线）

> 需要你准备：一个 GitHub 账号。本次交付**没有**替你推送任何代码，推送由拿到仓库地址和令牌后统一执行。

### 第 1 步：建两个仓库

在 GitHub 网页上新建两个仓库：

| 仓库 | 建仓库时勾选 |
| --- | --- |
| `info-workbench-site` | ✅ Public |
| `info-workbench-data` | ✅ Private |

**不要**勾选 "Add a README file"（我们已经有 README 了，勾了会冲突）。

### 第 2 步：把代码推上去

在本地电脑上装好 [Git](https://git-scm.com/downloads)，然后在终端里依次执行（把 `你的用户名` 换成你的 GitHub 用户名）：

```bash
# ① 站点仓
cd info-workbench-site
git init
git add .
git commit -m "信息汇总工作台 · 站点首版"
git branch -M main
git remote add origin https://github.com/你的用户名/info-workbench-site.git
git push -u origin main

# ② 数据仓
cd ../info-workbench-data
git init
git add .
git commit -m "信息汇总工作台 · 初始数据 798 条"
git branch -M main
git remote add origin https://github.com/你的用户名/info-workbench-data.git
git push -u origin main
```

推送时如果提示输入密码：GitHub 已不支持用账号密码推送，密码位置填**访问令牌**（见下一节）即可。

### 第 3 步：给站点仓打开 GitHub Pages

1. 打开站点仓 `info-workbench-site` → 顶部标签栏点 **Settings**（设置）
2. 左侧菜单点 **Pages**
3. "Build and deployment" 区域里：
   - **Source** 选 **GitHub Actions**
   - **Branch** 选 `main`
4. 点 **Save**

页面会提示"Pages 正在构建"。首次构建约 1～3 分钟，完成后出现绿色横幅：

> Your site is live at https://你的用户名.github.io/info-workbench-site/

**把这条网址记下来，这就是工作台的入口。**

### 第 4 步：确认数据仓里数据文件在

打开数据仓 `info-workbench-data`，在文件列表里应能看到：

- `data/records.json`
- `data/schema.json`

这两个文件是工作台的数据来源。缺任何一个，网页会提示"远端数据文件缺失"。

> v6.1.1 起，原来的 `data/pending-conflicts.json`（迁移期静态待确认清单）已从数据仓移除：
> 待确认项改由页面按当前数据**实时核对**（规则见站点代码 `src/store/pendingChecks.ts`），
> 修复记录后条目自动从清单消失，不再依赖静态快照。

### 第 5 步：在网页里配置令牌并连通

打开上一步拿到的网址 → 点顶栏 **设置** → 按下一节填写令牌 → 点 **保存并连接** → 页面显示"已连接"，并且记录条数变成 798。

### 第 6 步：确认自动备份已启用

打开数据仓 → 标签栏 **Actions** → 左侧能看到 **每周数据备份**（workflow 名 `backup.yml`）。

- 绿色的 ✅ 表示定时任务配置正常
- 点进去点 **Run workflow** 可以**立刻手动跑一次**备份，第一次跑完就能看到 `backups/` 目录

## 四、配置访问令牌（图文步骤）

令牌 = 一把只对你自己的数据仓有效的钥匙。**它只存在你浏览器的本地存储里**，不会进代码、不会进网址。

### 4.1 先说明：选哪种令牌

推荐用**细粒度令牌（Fine-grained personal access token）**，它可以精确限定"只能碰这一个仓库、只能读写文件"。

> 老式的 classic token 权限是整个账号级别的，一泄露你所有仓库都危险，不要再用。

### 4.2 生成令牌（逐步图文说明）

1. 登录 GitHub → 右上角头像 → 点 **Settings**（设置）
2. 左侧菜单最下面 → **Developer settings**（开发者设置）
3. 左侧 **Personal access tokens** → **Fine-grained tokens**（细粒度令牌）
4. 点绿色按钮 **Generate new token**
5. **Token name**：填 `信息汇总工作台`（只是个名字，方便以后辨认，可以随时删）
6. **Expiration**：选 **90 days** 或 **1 year**（到期后重新生成一张就行，工具会提示你换）
7. **Repository access**：选 **Only select repositories**（仅限选中的仓库）
8. 展开 **Select repositories**，点搜索框输入 `info-workbench-data`，勾选它
   > ⚠️ **只勾数据仓**。不要勾站点仓，更不要选 "All repositories"
9. 往下找到 **Repository permissions**，点 **Contents** 这一行，右边下拉框选 **Read and write**
   > 只勾这一项权限。**不要**勾 Actions / Pages / Workflows / Administration / Webhooks / Repository variables
10. 页面拉到底，点 **Generate token**
11. 生成后**页面只显示这一次**，全选复制下来（形如 `github_pat_11AA22BB…`）
    > 关闭弹窗就再也看不到了，只能重新生成

### 4.3 填进工作台

1. 打开工作台 → 顶栏 **设置**
2. **仓库地址**：填 `https://github.com/你的用户名/info-workbench-data`（也可以只填 `你的用户名/info-workbench-data`）
3. **分支**：默认 `main`，不用改
4. **访问令牌（PAT）**：粘贴刚才复制的令牌
5. 共享电脑请勾上 **仅本次会话有效**（关闭浏览器后令牌自动失效）
6. 点 **保存并连接**

看到 **已连接** 就成功了。想确认授权范围对不对，点 **测试连接**。

### 4.4 令牌使用须知

- ✅ 令牌**只存在你的浏览器本地**，清除浏览器数据就没了
- ✅ 站点仓里**不含任何令牌**，闸门脚本每次发布都会检查
- ❌ 不要把令牌贴在聊天窗口、邮件、截图里
- ❌ 不要把令牌写进任何仓库文件（包括数据仓的 `records.json`）
- ⚠️ 怀疑泄露了？回 GitHub → Developer settings → Personal access tokens → 点这张令牌 → **Revoke**（吊销），然后重新生成一张
- 🔁 换新令牌后，回工作台设置页把旧令牌删掉、粘贴新的、保存即可

## 五、日常使用：筛选、搜索、看板、增删改

### 筛选（多条件）

左侧 **筛选面板** 按字段分组：品牌、分类、款式、季节、教程、推荐、想做、电子版尺码组，以及几个"是/否/不限"开关（拥有电子版、拥有纸质版、电子版缺码、做过）。

- **同一个字段内多选**是"或"：勾选「女装」和「男装」，两个都算命中
- **不同字段之间**是"且"：同时选「品牌 = 某品牌」和「季节 = 夏」，只显示同时满足的
- **三个开关**是三态：不勾＝不限，勾"是"＝只要符合条件的，勾"否"＝只要不符合条件的
- 点 **清空筛选**恢复全部

### 搜索（全文）

顶栏搜索框，输入即搜，范围覆盖 **名称、品牌、备注** 三个字段。

- 多个词用空格分隔，取**交集**（同时包含才算命中）
- 命中的文字会**高亮**
- 搜索和筛选**叠加生效**

### 排序

点表头可切换：记录 ID、名称、品牌、更新时间。每个字段点一次升序、再点一次降序。

### 网址会记住你的状态

筛选、搜索、排序、页码都写进网址，例如：

```
https://你的用户名.github.io/info-workbench-site/#/list?brand=某品牌&cat=女装&q=羊毛&sort=名称&dir=asc&page=2
```

把这条网址收藏或发给同事，打开就是同样的视图；从详情页返回列表，筛选条件也不会丢。

### 新增 / 编辑 / 删除

- **新增**：列表页右上角 **＋ 新增记录** → 填表 → 保存
- **编辑**：点记录名进详情页 → **编辑** → 改完保存
- **删除**：详情页或列表页的 **删除** 按钮 → 二次确认 → 记录**立即从数据中移除**（v4 已移除回收站，无法恢复）
- 删除是**物理删除**：记录马上从列表、看板和导出里消失，下次同步会把这次删除写回仓库
- 删错了只能从备份恢复：删除前先到 **设置 › 数据管理** 导出一份备份

### 看板

顶栏 **看板**：

| 图表 | 看什么 |
| --- | --- |
| 品牌分布 | 各品牌记录数（前 10 + 其他） |
| 分类分布 | 各分类记录数（一条记录命中两个分类就计两次） |
| 款式分布 | 各款式记录数 |
| 季节分布 | 各季节记录数（空值归入"未填"） |
| 拥有形态 | 只有电子版 / 只有纸质版 / 两者都有 / 都没有 |
| 完成与计划 | 做过 / 想做 / 还没做的量级 |

顶部 KPI 卡片：总记录数、做过数、想做数（v4 已移除「有教程数」口径）。

## 六、数据导出与恢复

顶栏 **设置** → **数据管理**（v4 起导出入口只在这里，列表页不再放导出按钮）：

- **导出全部 JSON**：与数据仓 `records.json` 同构，含全部字段，**可以再导回去**
- **导出全部 Excel（.xlsx）**：两张工作表 —— 「数据」是明细，「看板统计」是各维度计数
- 两种格式都支持 **导出全部** 或 **只导出当前筛选命中的记录**（口径与列表页一致）

文件名固定格式：`信息汇总工作台-数据-YYYYMMDD.json` / `.xlsx`

### 恢复（万一改错了）

1. 在工作台里 **导出 JSON**（选"全部记录"），存到电脑
2. 出问题后，用 GitHub 网页打开数据仓 → `data/records.json` → 右上角铅笔图标编辑
3. 把整个文件内容替换成你导出的那份 JSON，提交（Commit）时写一句说明
4. 回到工作台点 **拉取**，数据即恢复

> 也可以直接把导出的 JSON 存成 `data/records.json` 覆盖，用 GitHub 网页上传替换同样可行。

## 七、备份机制（自动 + 手动）

一共三层，任意一层出问题都能回退：

### 第 1 层 · 主数据

数据仓里的 `data/records.json` —— 唯一事实源。每次在网页上点 **同步**，就会带版本号提交一次（提交信息形如 `工作台同步 12 · 798 条 · 2026-10-30T…`）。

### 第 2 层 · 每周自动快照

数据仓的 `.github/workflows/backup.yml`：

- 每周一 **凌晨 3:17**（UTC）自动跑一次
- 把当前 `data/records.json` 复制成 `backups/records-YYYY-MM-DD.json`
- **保留最近 26 周**，更早的自动删除
- 内容没变化时会跳过提交，不产生无意义的版本记录

**手动立刻备份一次**：数据仓 → Actions → 左侧选「每周数据备份」→ 右侧 **Run workflow** → 绿色 Run workflow。

**从快照恢复**：数据仓 → `backups/` 目录 → 找到需要的那天 → 下载文件 → 覆盖 `data/records.json` → 提交。

### 第 3 层 · 手动导出

随时在工作台点 **导出**，把 JSON / Excel 存到电脑或网盘。与前两层完全独立，不依赖 GitHub。

> 三层建议的节奏：每周看一眼 Actions 有没有绿勾；每月导出一次 JSON 存网盘；换电脑或迁移前一定导出一次。

## 八、常见问题排查

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 页面显示"尚未配置仓库" | 没填仓库地址/令牌 | 进 **设置** → 填好 → 保存并连接 |
| 提示"令牌无效或已过期" | 令牌被吊销或到期 | 重新生成令牌，粘贴新的 |
| 提示"令牌权限不足" | 授权范围不对 | 检查令牌是否勾了数据仓 + `Contents: Read and write` |
| 提示"找不到仓库或文件" | 仓库名/分支/路径不对 | 仓库地址填 `用户名/info-workbench-data`；确认 `data/records.json` 存在；分支是否 `main` |
| 提示"远端文件已被更新，需要先处理冲突" | 另一台设备或网页标签页改过同一份数据 | 弹窗里三选一：**以本地为准覆盖** / **以远端为准** / **合并后保存**（合并会把双方改动合起来，冲突字段单独列出） |
| 顶部横幅"有未同步的本地改动，已暂停自动拉取" | 你改了数据但还没点同步就关了网页，重开时网页**不会**自动用远端覆盖你的改动 | 按横幅提示二选一：点 **同步写回仓库** 把本地改动写回，或先点 **先导出本地副本** 备份，再自行处理远端更新 |
| 同步时提示"远端已是最新，无需写入" | 你的改动其实已经在远端了，或远端被别人写了同样内容 | 无需处理，网页已自动对齐并刷新基线 |
| 提示"浏览器本地存储已满" | 缓存 + 待同步队列 + 同步基线超出了浏览器配额 | 先点 **导出本地副本**，再到设置页调小备份周期或清理浏览器存储 |
| 提示"内容被 GitHub 推送保护拦截" | 令牌权限过大，可能误把令牌写进了数据文件 | 换用细粒度令牌只授权 `Contents`，并检查数据文件里没有令牌 |
| 记录条数不是 798 | 本地缓存是旧的 | 点 **拉取**；若仍不对，检查数据仓 `data/records.json` 的 `recordCount` |
| 离线了打不开 | 没网 | 断网时如果之前拉取过，缓存仍在，可继续浏览/编辑；联网后再同步 |
| 改完没保存上 | 没点同步 | 编辑后点顶栏 **同步**；顶栏会显示"待同步 N 条" |
| GitHub Pages 打开是 404 | Pages 没启用或还没构建完 | 设置 → Pages → Source 选 GitHub Actions；Actions 页签看有没有红色失败 |
| 构建失败红色叉 | 类型错误或闸门拦截 | Actions 里点开失败步骤看日志；闸门拦截说明站点仓里混进了数据或令牌，按提示清理 |

### 关于「待人工确认清单」（v6.1.1 动态核对）

最初迁移时，原始 Excel 里有 20 处「勾选状态与尺码信息」相互矛盾的字段值，当时的做法是把它们写成数据仓里的静态清单（`data/pending-conflicts.json`）。这个清单是迁移那一刻的快照，之后**从不跟随数据更新** —— 你改对了记录，提醒也不会消失。

v6.1.1 起改为**动态核对**：每次打开工作台，页面按当前记录数据实时重算，规则沿用当初迁移工具的口径（并已同步到 v6.1 字段名）：

- 矛盾记录：拥有形态未勾选「电子版/纸质版」、但对应尺码已填写；或名称为空。
- 建议补全：拥有形态勾选了「电子版/纸质版」、但对应尺码为空。

行为约定：

- 你修复一条记录，它对应的条目**自动从清单消失**；全部处理完，横幅不再显示。
- 每条支持「忽略」（保存在这台电脑的浏览器本地，单人使用不上传），另有「全部忽略」；被忽略的条目不再出现在横幅里，但可在「设置 › 数据管理 › 待确认清单」查看并恢复。
- 系统从不自动翻转任何勾选值、不自动填值。
